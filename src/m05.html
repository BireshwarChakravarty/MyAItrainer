Working with data: tables, files and numbers

Prompting about data is different from prompting about words. This aisle shows you how to hand data to AI so that the numbers you get back are ones you can trust.

Time 30 minLevel IntermediateHands-on 1 lab + quiz

By the end of this aisle you will be able to

  • Choose the right way to give AI your data based on its size
  • Prepare a spreadsheet so AI (and Excel) can read it without errors
  • Ask for the method, not just the answer, so results are checkable and reusable

Prepare your data: the clean-table checklist

AI, Excel formulas, PivotTables and Power Query all struggle with the same things. Ten minutes of tidying saves an hour of confusion. The aim is a clean table:

Do

  • One header row, with clear names: System_Qty, not Qty
  • One row per record (one line per SKU per location)
  • One type of data per column: numbers as numbers, dates as dates
  • Same units throughout. Note them in the header: Qty_EA vs Qty_CASE
  • A column saying which warehouse each row belongs to
  • Format it as an Excel Table (Ctrl+T)

Avoid

  • Merged cells and multi-row headers
  • Subtotal or total rows mixed in with data
  • Blank rows or columns used as spacing
  • Colour as the only way of marking something
  • Notes typed into number columns ("approx 40")
  • Seven warehouses on seven differently-laid-out tabs

Give it a data dictionary

A data dictionary is a short description of each column. It is the single best way to stop AI misunderstanding your data. Put it at the top of your prompt.

Columns in the attached file:
- WH: warehouse code, WH01 to WH07
- SKU: item code
- UOM: unit of measure (EA = each, CS = case of 12)
- Sys_Qty: quantity in the WMS at count time, in UOM
- Cnt_Qty: physically counted quantity, in UOM
- Unit_Cost: standard cost per EA in USD
- Count_Date: date of the cycle count (DD/MM/YYYY)
- Counter_ID: anonymised counter code
Notes: a negative variance means stock is missing. Rows where UOM = CS must be multiplied by 12 before comparing to EA.

Ask for the method, not only the answer

This is the most important habit in this aisle. Instead of "what's the total variance?", ask the AI to give you the formula, the steps or the code. Three benefits:

  • You can check it. A formula is either right or wrong. A number on its own is a black box.
  • You can reuse it. Next month, apply the same formula to new data without AI at all.
  • Your data stays put. You can get the formula using fake data, then apply it to the real thing.
I have an Excel Table called Counts with columns WH, SKU, Sys_Qty, Cnt_Qty, Unit_Cost.
Write me formulas (Microsoft 365) for new columns:
1. Var_Qty (counted minus system)
2. Var_Pct (variance as % of system qty, handling system qty = 0 safely)
3. Var_Value (variance quantity × unit cost)
4. Out_Of_Tolerance ("YES" if absolute Var_Pct is over 2%, else "NO")
Explain each formula in one sentence. Then give me a formula that counts out-of-tolerance lines per warehouse.

When uploading a file: force real calculation

If your assistant supports file analysis, add these lines so it uses code rather than guessing:

Use code to analyse the file. Don't estimate.
First, tell me: the sheet names, the number of rows and columns you loaded, and the column names.
After your analysis, give me control totals (row count and sum of [Var_Value]) so I can tie them to my Excel file.
Show me the key steps you ran.

What a good data conversation looks like

Here is a realistic exchange. Notice how the person checks before trusting, and refines rather than restarting.

You

[Uploads October_Counts.xlsx] Here are October cycle counts for 7 warehouses. Using code, first tell me the row count per warehouse and the total of Var_Value.

AI

Loaded 1 sheet, 2,418 rows. WH01: 402, WH02: 311, WH03: 288 … Total Var_Value: −$18,946.20.

You check: Excel shows 2,418 rows and −$18,946.20. Totals tie. Now you can trust the analysis.
You

Good, that matches. Which warehouse has the worst inventory record accuracy, counting a line as accurate if within ±2%?

AI

WH05 at 91.4% (36 of 418 lines outside tolerance). Most of WH05's misses are on SKUs with UOM = CS.

You

Interesting. Did you convert cases to eaches before comparing? Show me 5 of those WH05 rows with the raw values.

This is the key move: when something looks interesting, ask to see the underlying rows. A unit-of-measure issue might be a real finding, or an AI mistake.

Key takeaways

  • Small data: paste it. Large data: upload to a tool with data analysis, or work in Excel with Copilot.
  • Clean tables (one header row, no merged cells, consistent units) make everything work better.
  • Always give a data dictionary, and always check row counts and totals first.
  • Ask for formulas and steps, not just answers. They're checkable and reusable.
